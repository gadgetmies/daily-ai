## A Claude Code agent deleted 48,000+ files in under two minutes — and the rewind feature wouldn't have saved them

A widely circulated developer report (via Reddit, with an attached "verifier" report) describes a Claude Code agent tasked with rebuilding a directory mirror. When its rebuild script (`build_mirror.py`) couldn't refresh the mirror in place, the agent wrote its own cleanup script to clear an older mirror copy — which turned out to contain Windows directory junctions pointing back into the live project tree. The cleanup script followed the junctions and deleted straight through them, wiping 48,218 live files and the repo's Git object store in 103 seconds. The agent's own message afterward: "stop and read this... I broke something."

This is a single user's account, not an independently confirmed forensic investigation or an Anthropic disclosure, so treat the specifics as reported rather than verified. But the underlying mechanism — and the lesson about Claude Code's `/rewind`/checkpoint system — checks out against Claude Code's own documentation: rewind only restores edits made through Claude's file-editing tools, not deletions via shell commands like `rm`, and it explicitly skips symlinks and junctions. Takeaway: don't rely on built-in checkpointing as a safety net for bulk/mirror/junction-involving operations — make sure real commit history or external backups are in place before an agent run starts, especially for longer, less-supervised autonomous sessions.

## GitHub's Copilot CLI now reads Claude Code's own rule files

GitHub Copilot CLI release 1.0.89-5 (27 September) adds native support for Claude Code's custom rule files as its own custom instructions, alongside smaller UX and sandbox-logging fixes. Practical effect: teams running both Claude Code and Copilot CLI no longer need to maintain two separate instruction files.

So-what: a small compatibility patch on its own, but part of a broader convergence of coding agents on shared conventions for project instructions — worth adopting today if you already maintain a Claude Code rules file, and worth watching as a trend if more vendors follow suit.

## Cursor lets teams run its cloud coding agents on their own infrastructure

Cursor shipped team-wide "worker pools" (2 September) letting Cursor's cloud agents keep planning/reasoning on Cursor's servers while executing file edits, terminal commands, and builds on infrastructure you control — a laptop, VM, Kubernetes cluster, GPU box, or a supported sandbox backend (Coder, Daytona, E2B, Modal, Namespace, Vercel, AWS Lambda, Cloudflare). Workers only need outbound HTTPS to Cursor, so no inbound endpoint has to be exposed. Autoscaling and hibernation mean idle workers stop costing anything.

So-what: removes the previous blocker where Cursor's cloud sandbox couldn't reach private source control, internal services, custom build tooling, or specialized hardware — worth trying now for teams that held off on cloud agents for exactly that reason.

## Richard Socher's Recursive is betting on fully automating the scientific research loop

Richard Socher (former Salesforce chief scientist), with co-founders from OpenAI, Meta AI, and Google DeepMind backgrounds, launched Recursive (formerly "Recursive Superintelligence") out of stealth with $650M raised at a $4.65B valuation, led by GV and Greycroft, with Nvidia and AMD Ventures participating. On the Latent Space podcast ("Humanity's Last Invention"), Socher laid out a "Eureka Machine": automating the full research loop — ideation, implementation, and validation — via four pillars (a knowledge base of existing science, scientific measurement data, simulations, and physical lab experiments) orchestrated by a swarm of AI agents, with no human in the loop deciding what to try next.

So-what (research/vision, no product yet, <30 employees): distinct from research-assistant tools covered previously (e.g. Google's ERA, which still keeps a human choosing the question) — this is a bet on removing the human from every stage, including the expensive, slow physical-experiment pillar most "AI for science" efforts skip. Worth tracking as a signal of where frontier-lab ambition and capital are heading, not as something to use.

## GPT-6 (Astra) produces the first verified solution to a genuinely unsolved Erdős problem

Epoch AI reports GPT-6 Astra set a new Epoch Capabilities Index record (169, up from 163 — a jump Epoch itself calls within the normal trend range, not a break from it). More notable: on Epoch's FrontierMath Erdős set — 68 genuinely unsolved Erdős problems in number theory/combinatorics, curated by mathematician Thomas Bloom, with solutions required in the Lean formal-proof language for mechanical verification — no model had solved any before. Astra solved 2 of 68. Astra also reached 98% on the older FrontierMath Tier 4 set (closing its last remaining problem) and set records on continual-learning and game-puzzle evals (84% on "Mystery Game Puzzles" vs. the prior best of 59%, held by Claude Opus 5).

So-what (research/further out): the formal-proof requirement means no partial credit for a plausible-sounding wrong answer, and no training-data contamination is possible since no solutions to these problems existed to train on. 2 of 68 is a small number, but it's the first verified instance of a model producing a new result no human mathematician had — categorically different from matching a known answer. Not something to build on this week, but a real existence proof that "AI produces genuinely new results" now has real, if rare, instances.
