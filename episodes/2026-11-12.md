## 1. Gemini Decisions API and the arrival of "decision models" — *today*

Google launched the Gemini Decisions API (model `gemini-decision-1`) on 11 November. Instead of generating text, the model scores a set of bounded questions (yes/no, multiple choice up to 255 options, rubric scores; up to 1,000 per request) against one shared multimodal input (text, image, audio, video, PDF, up to 256K tokens) in a single forward pass, returning probabilities and confidence. Google quotes ~150–250 ms end-to-end latency, flat from 1 to 100 questions, and $0.10 per million input tokens with no output charge; there is a free tier in AI Studio. Day-zero integrations: LangChain, OpenRouter, Vercel, LiteLLM.

Context: OpenAI opened a Decisions endpoint on GPT-6 Luna in October at the same $0.10/M input price. Latent Space's AIE CODE recap ("D-Day") notes Google beat Anthropic to a production decision model. Independent measurement: Artificial Analysis Decision Index v2.1 ranks Gemini Decision 1 ninth of 18 (66/100), behind Drex Max v1.1 and GLiDE v1.2 (73). Google reports ECE 0.0250 vs 0.0494 for Jev 1.14 on its own suite; Artificial Analysis's Brier scores (~0.18 Gemini, 0.16 Drex, 0.19 Jev) are roughly level — different metrics, not directly comparable. Simon Willison tested it on a video file and noted less extreme yes/no confidence than rivals.

## 2. AWS Emulator: a free local AWS, written and maintained by agents — *today*

Released 11 November. Runs locally, answers AWS API calls over a local HTTPS endpoint; point the CLI/SDKs at it via `AWS_ENDPOINT_URL`. Generates its own credentials, config and certificate on first start. Linux: RPM/DEB packages; macOS/Windows: Docker image. Unsupported operations return `501 Not Implemented` so tests fail loudly. AWS publishes per-service "k of n" fidelity scores per release and tracks known gaps in a `things-that-do-not-work` folder; one third-party tally of the fidelity file found ~56.5% of tests passing (unofficial snapshot). Positioned for development/testing, not security validation.

AWS says the code was written and tested entirely by autonomous agents from published API models (200+ services per AWS; other outlets say 426 services / 438 API models — counts conflict); humans built specs, test machinery, merge gates and release pipeline, and agents maintain it. Source on GitHub under CC0 1.0 (vendor dir Apache-2.0). The "no pull requests, issues only" claim comes from a single outlet (Unite.ai).

## 3. Railway incident report: stolen AI keys ran up ~$740,000 — *today*

Railway published its full report on 10 November for the October breach. Attack chain (per report coverage): a previously unknown flaw in the multi-tenant build system allowed partial filesystem-isolation escape; an erroneously defined OIDC binding yielded short-lived cloud credentials, leading to an SSH key and then a longer-lived credential able to decrypt customer environment variables. Because variables were envelope-encrypted, Railway cannot enumerate exactly which were decrypted; upper bound is 1.85% of workspaces (~100,000). 1,852 linked-account tokens (incl. GitHub OAuth) were reset; no logins to Railway accounts with stolen credentials observed. Stolen keys were used against Amazon Bedrock, OpenAI, Anthropic and Google Gemini for an estimated ~$740,000 (estimation method not stated). Railway's forensics reportedly point to resale through relay services, with output used for distillation (single-source detail). Refund positions differ: Bedrock and Gemini refunding under fraud policies, OpenAI reviewing individually; Railway says it will cover refused charges, though a Cloud Security Alliance note observes its claim form disclaimed responsibility. Advice: rotate at the downstream provider, set spend limits and alerts, use short-lived scoped credentials, monitor inference usage. Related to yesterday's Fireworks AI item (LLMjacking pattern).

## 4. Chrome's Modern Web Guidance 1.0 for coding agents — *today*

Version 1.0 announced 10 November (project previously in preview; docs pages date to late October). A skills pack that steers coding agents toward native, Baseline-grounded web platform features and away from legacy patterns. Defaults to Baseline "Widely available"; a project can declare another target (e.g. Baseline 2024) in AGENTS.md/CLAUDE.md. Install: `npx modern-web-guidance@latest install`, or via agent plugin marketplaces. 1.0 adds a codebase audit mode; Firefox and Edge have joined the project. Google runs a nightly eval dashboard across Anthropic, OpenAI and Google agents with/without guidance; one summary reports 88% vs 56% of checks passed (secondary source; feature counts vary by outlet: 102–250 features).

## 5. Qwen4-Max-Preview ("Qoduck") — *soon*

Reported specs: 1M-token context, 393,216-token output ceiling shared between reasoning and answer, three reasoning-effort levels, text/image/video input, OpenAI- and Anthropic-compatible API formats. No per-token price; metered in credits against subscriptions from ~$3–6/month, with a preview discount and a further overnight discount (outlets disagree on the exact overnight rate). No benchmarks published; early impressions: very fast, hit-and-miss on complex coding.

## 6. DeepMind AlphaProof Code formally verifies Signal's core at machine-code level — *research*

Published 10 November. Three components: a human-guided agent that writes Lean specifications (humans formalise and approve Signal's security goals); a formal semantics of AArch64 machine code; and autonomous prover agents whose proofs count only if Lean's kernel accepts them against the approved spec. Target: libsignal-cli built by stock rustc from unmodified libsignal v0.105.4 and SPQR crates. Properties: forward secrecy, authentication, post-compromise security, handshake secrecy for PQXDH and the Triple Ratchet. ~6.5M lines of machine-checked Lean on ~26K lines of trusted spec/semantics; audit flagged ~1% for human review; five-person team, four weeks. Trust base: Lean kernel + AArch64 semantics, not the Rust source or compiler. Validation: two previously fixed bugs were reintroduced and the proofs showed those builds violate the symbolic security theorem. Limits: protocol core only, not the whole app; cryptographic properties, not memory safety; no new vulnerabilities found; no weights/endpoint — Lean development and specs published on the project site. HN thread questions the scope of what was proven.
